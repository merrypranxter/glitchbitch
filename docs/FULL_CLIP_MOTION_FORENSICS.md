# Glitchbitch — Full-Clip Motion Forensics (three checkpoints)

**Feature branch:** `feature/full-clip-motion-forensics`  
**Follows:** Real Encoded Frame Truth Serum PR #73, text-clock synchronization PR #72.  
**Availability:** Export → Video, after producing a real MP4 or GIF → **Full-Clip Motion Forensics · opening / middle / final**.

## The specific problem

An exported MP4/GIF can appear technically valid yet contain little or none of the motion visible in the generative art preview. A single decoded frame, even compared against a strict PNG, cannot distinguish an intentionally still artwork from a video with lost animation or detect a frozen middle/end.

This upgrade compares **three real decoded frames from the exported file** against three fresh, same-clock **strict-effects PNG references**. It does not infer motion merely because `clockAt`, GIFEncoder or CanvasSource exists in source code.

## What the forensic check actually does

1. Hold onto the **actual saved clip Blob** in the Export dialog. No video is re-encoded.
2. Select the **opening**, **middle** and **final** frame indices from the original encoder frame count and fps. Index 0, `floor((count-1)/2)`, and `count-1`.
3. Decode the actual media frames:
   - **GIF:** use the bundled decoder in `src/clip-motion-forensics.js`, which parses the app's **full-frame, noninterlaced GIF89a** blocks and decompresses original GIF LZW indices and per-frame color tables. It has been tested against GIF bytes generated by **the exact vendored `gifenc` encoder**. It refuses arbitrary subrect/interlaced/transparency GIF layouts rather than returning guessed pixels. This bypasses optional `ImageDecoder` support on iOS Safari.
   - **H.264 MP4:** reuse one muted, invisible, inline `HTMLVideoElement` and seek to each requested portion. Wait for decoded-current-data events and use `currentTime` as the decoded media timestamp. Frame seeking may be codec/keyframe-dependent; if the decoder reports repeated timestamps, the diagnosis becomes **inconclusive**, never an accusation.
4. Temporarily release the main WebGL preview, decode the clip checkpoints **before** opening the PNG reference GPU, and keep three decoded frames at most at a maximum 480px inspection edge. The diagnostic is offered only for **480px or 720px** clips on iPhone to protect memory. Your full-resolution exported file is unchanged.
5. Re-render each reference at the **actual exact encoded dimensions**, including the MP4 even-pixel rounding of a 9:16 720p clip. Use the same pure `clockAt(state,timeline,seconds)` as the MP4/GIF encoder and enforce `{exactEffects:true}`. Any error rejects the diagnostic instead of secretly disabling effects.
6. For GIFs, use the original **frame index / fps** for the PNG shader clock, even though the GIF's actual display delays are rounded to **10 ms** (e.g. 15 fps's 66.67 ms becomes 70 ms). Both the intended PNG time and actual GIF display time are reported separately.
7. For MP4s, use the decoded **HTMLVideoElement.currentTime** for the reference clock; record any divergence from the nominal requested checkpoint.
8. Measure *actual change* between decoded frame 1→2 and frame 2→3, versus change between the corresponding strict PNGs. Uses sampled mean RGB channel delta, changed-pixel percentage, and p95 difference. Only flags **possible frozen or lost encoded motion** if **the PNG references clearly change** while the encoded frames are nearly stationary.
9. Show a selectable opening/middle/final comparison with three images: strict PNG reference, **real decoded GIF/MP4 frame**, 4× amplified discrepancy heatmap.
10. Export a small **privacy-safe JSON** with frame indices, clocks, decoder time confidence, coarse discrepancy/motion statistics and file dimensions. **No original lettering, palette colors, screenshot pixels, or raw video** are sent anywhere.

## How to use it

1. Pull the merged branch in Google AI Studio.
2. Export a **2–6 second GIF or MP4** at **480px or 720px**. For a convincing test, choose an unmistakably animated design with Filament motion, Quasicrystal drift, Feral migration, optical motion, Retrocausal stitches, moving text or another visibly animated effect.
3. While the Export dialog remains open, tap **Full-Clip Motion Forensics · opening / middle / final**.
4. Compare reference and decoded frame images for each checkpoint, and look for large missing swathes of light, optical dress, stitches and colors. Check the motion-retention value.
5. If the report says **Possible frozen or lost encoded motion**, save the JSON report and share the three screenshots of the sample comparisons with the issue. A low motion-retention value alone is not a certified encoder bug.
6. If it says **No reliable motion expected from these PNG samples**, the selected reference images may be genuinely static, too subtly changing, or sampled at a periodic repeat. This is **not a successful full-clip parity verdict**.
7. If it says **Inconclusive: decoder timestamps did not advance**, Safari did not return sufficiently separated MP4 checkpoints; this is a diagnostic-decoder limitation, not proof of a frozen exported MP4.

## What this does **not** prove

- Only **three checkpoints**, not all 30 seconds of animation. A video can freeze in a segment between those samples.
- **GIF palette quantization**, dithering, 10-ms delay rounding and **H.264 compression/chroma subsampling** will alter pixels even when shaders render correctly.
- **Native Safari MediaRecorder** may have variable frame timing or dropped frames; seeking samples an approximate reported media time, not a cryptographic guarantee of the original source frame index.
- **Feedback, afterimage, datamosh, evolving history** can diverge from freshly rendered strict PNGs because a short history primer is not identical to the first several seconds of the original clip. This can inflate per-frame discrepancy or produce nontrivial motion differences; interpret the image comparison before blaming the encoder.
- Cyclic animation can land at similar first/middle/end positions, even while it moves smoothly between them.
- No claim of CSS/DOM live-preview lettering pixel-perfect parity, seamless loops, audio, or full duration certification.

## Code and performance

- `src/clip-motion-forensics.js`: pure motion statistics and conservative warnings; GIF89a parser + bounded LZW; three-frame MP4 native decoder; 480px downsampler; privacy-safe report helper.
- `src/components/ExportDialog.jsx`: optional three-sample audit in the existing Video export dialog, selectable image triptychs, 480/720 cap, progress labels and URL lifecycle.
- `tests/clip-motion-forensics.test.mjs`: actual bundled encoder → decoder round-trips (including 128×96 varied patterns), synthetic freeze/no-motion/motion-preserved cases, timestamp-inconclusive safeguard, mismatched dimensions, privacy, and exact clock/wiring.
- **No changes** to the GIF or MP4 encoder, existing `createFrameWorkspace` or `recordClip` logic. No new Netlify deployment is requested.
